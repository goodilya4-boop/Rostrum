# Rostrum Backend

Backend приложения «Трибуна»: Express API, PostgreSQL, обработка презентаций, хранение репетиций и анализ речи.

## Реализовано

- регистрация, вход и JWT;
- профиль, настройки и смена пароля;
- загрузка PPTX/PDF через Multer;
- извлечение текста и формирование изображений слайдов;
- закрытый доступ к исходным файлам и изображениям;
- создание, проведение и завершение репетиций;
- приём финальных сегментов Web Speech;
- анализ тезисов, темпа, слов-паразитов и соблюдения регламента;
- повторный анализ с версией алгоритма;
- SQL-миграции и транзакции;
- структурированные ошибки и rate limiting;
- интеграционные и модульные тесты.

Vosk остаётся экспериментальным модулем. API сообщает `status: development`, `available: false`, а создание Vosk-сессии возвращает `501`. Код контракта сохранён, чтобы продолжить разработку позднее.

## Требования

- Node.js 18+;
- PostgreSQL;
- npm;
- необязательно: LibreOffice и `pdftoppm` для нативных изображений.

Без нативного renderer Backend создаёт безопасные SVG-превью.

## Настройка

```powershell
npm install
Copy-Item .env.example .env
```

Основные переменные:

| Переменная | Назначение |
| --- | --- |
| `PORT` | порт API, обычно `3000` |
| `DB_HOST`, `DB_PORT` | адрес PostgreSQL |
| `DB_NAME`, `DB_USER`, `DB_PASSWORD` | подключение к базе |
| `JWT_SECRET` | ключ подписи токенов |
| `CORS_ORIGIN` | разрешённый адрес Frontend |
| `UPLOAD_DIR` | приватный каталог загрузок |
| `SLIDE_IMAGE_DIR` | каталог изображений слайдов |
| `LIBREOFFICE_PATH` | путь к LibreOffice |
| `PDFTOPPM_PATH` | путь к Poppler `pdftoppm` |
| `RATE_LIMIT_MAX` | общий лимит API |
| `REHEARSAL_RATE_LIMIT_MAX` | отдельный лимит запросов репетиции |

Параметры `VOSK_*` зарезервированы для дальнейшей разработки и сейчас не включают функцию.

## База и миграции

Создайте пустую базу, заполните `DB_*`, затем выполните:

```powershell
npm run migrate
```

Мигратор:

- хранит применённые версии в `schema_migrations`;
- проверяет контрольные суммы;
- использует advisory lock;
- применяет каждую миграцию в транзакции.

Повторный запуск безопасен.

## Основные маршруты

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `POST` | `/api/auth/register` | регистрация |
| `POST` | `/api/auth/login` | вход |
| `GET/PATCH` | `/api/users/:id` | профиль и настройки |
| `POST` | `/api/presentations` | загрузка PPTX/PDF |
| `GET` | `/api/presentations/:id/slides` | метаданные и слайды |
| `GET` | `/api/presentations/:id/slides/:index/image` | защищённое изображение |
| `POST` | `/api/sessions` | создание репетиции |
| `POST` | `/api/sessions/:id/slide-changes` | переключения слайдов |
| `POST` | `/api/sessions/:id/transcripts` | сегменты Web Speech |
| `PATCH` | `/api/sessions/:id/complete` | завершение и анализ |
| `POST` | `/api/sessions/:id/reanalyze` | повторный анализ |

Все пользовательские маршруты проверяют JWT и владельца ресурса.

## Web Speech

Распознавание выполняется браузером. Backend получает только финальные сегменты:

```json
{
  "segments": [
    {
      "segment_id": "web-session-uuid",
      "start_ms": 1000,
      "end_ms": 2500,
      "spoken_text": "текст выступления",
      "confidence": 0.9
    }
  ]
}
```

`segment_id` обеспечивает идемпотентность повторной отправки.

## Презентации и файлы

- Допустимы только `.pptx` и `.pdf`.
- MIME и расширение проверяются совместно.
- Физические пути никогда не возвращаются клиенту.
- Изображения доступны только владельцу через API.
- Имя файла нормализуется и корректно декодируется из multipart.
- Слайды и метаданные создаются в одной транзакции.

## Тесты

```powershell
npm test
```

Тесты выполняются последовательно, чтобы не создавать несколько тяжёлых интеграционных процессов одновременно.

## Структура

```text
src/
  config/       окружение, БД, OpenAPI
  controllers/  HTTP-контроллеры
  db/           схема, мигратор и миграции
  middleware/   JWT, загрузки, ошибки, лимиты
  models/       SQL-доступ
  routes/       маршруты API
  services/     бизнес-логика, парсинг и анализ
  utils/        общие функции
test/           модульные и интеграционные тесты
vosk-service/   экспериментальная заготовка, не production-компонент
```

## Известные ограничения

- Vosk находится в разработке и отключён.
- Production deployment пока не стандартизирован.
- Для настоящего PPTX-rendering требуется LibreOffice.
- Для PDF-изображений требуется Poppler.
